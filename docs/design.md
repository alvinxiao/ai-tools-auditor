# Local catalog design

The application retrieves captions through isolated yt-dlp or accepts supplied transcripts, then turns researched assessment JSON into Obsidian reports. Subscription execution remains outside the application.

The domain is a versioned catalog of videos, stable tool identities, immutable assessments, and comparisons. Video state is explicit: queued, blocked, ready, audited, or failed. Transcript attachment makes a video ready. A validated import makes it audited. Retry retains a transcript.

`src/cli.mjs` owns commands and persistence sequencing. `src/auditor.mjs` owns identity, evidence rules, packets, and Markdown projection. `src/store.mjs` owns process locking and flushed file replacement. `src/vault.mjs` owns generated-section boundaries.

## Synthesis decision

Two independent proposals compared JSON with SQLite and an append-only event log. JSON was selected because one local CLI writer needs no database package or replay engine. The event-log proposal contributed content-hash assessment snapshots and rebuildable Markdown. SQLite becomes useful if parallel workers or larger queries are needed.

An exclusive `catalog.lock` prevents simultaneous CLI writers. A mutation validates inputs, writes an assessment snapshot when relevant, commits the catalog, and renders notes. Pre-commit interruption may leave harmless orphan snapshots. Catalog state is authoritative. A failed render can be retried with `render`.

Each file is flushed before replacement. New notes use an exclusive hard link from the completed temporary file. Updates use sibling rename. The workflow is not a transaction across the whole vault and does not claim protection against disk failure. After a crash, remove the lock manually only after confirming no writer is running.

## Evidence and identity boundaries

An import is a research assertion. Validation cannot prove that a cited source supports a claim. It checks fields, evidence kinds, dates, identity, and recommendation eligibility. Positive verdicts need current verified non-video evidence. Comparisons require both participants refreshed in the same import and preserve their exact assessment snapshots. Reports become stale after 30 days.

Canonical URLs must match existing stable product IDs. Conflicts fail rather than merging by name. Aliases and existing identities are supplied to the researcher. The first slice does not infer equivalence between different URLs or implement fuzzy matching.

Packets include transcripts and notes as untrusted data. They request current source research, practical build versus buy, and visual-inspection disclosure. The CLI does not invoke a model, execute transcript contents, download software, or read credentials. Evaluation profiles are configurable local text.

## Output ownership

Every generated note preserves content outside marked sections. Missing or duplicate markers fail closed. Avoid simultaneous manual editing during render. The CLI lock cannot coordinate an external editor. Personal annotations are included in later packets.

Current comparisons live in `Comparisons`. Dated assessment and comparison snapshots live in `History`. Sources use hex-encoded video IDs to preserve case distinctions on Windows. Categories and dashboard pages derive from committed state. Unchanged repeat coverage adds source links without another changed-assessment entry.

`src/retrieval.mjs` verifies the pinned artifact and runs it in an existing reviewed container with only scratch output and the artifact mounted. No software acquisition occurs automatically. Retrieval clears obsolete transcripts on failure, parses complete JSON3 captions on success, and records a cooldown for HTTP 429. The CLI retains the catalog lock during retrieval to serialize mutations.

`src/discovery.mjs` performs explicit manual channel discovery over YouTube's public Atom feeds; it is preparatory and enables no ongoing monitoring, so `catalog.monitoring` stays false and no scheduler exists. `catalog.channels` is an optional map that v1 catalogs gain lazily. Each channel record holds `{id, addedAt, initialized, seenVideoIds, lastCheckedAt, state: configured | ready | failed, reason?, retryAfter?}`. Only exact `UC` + 22-character IDs are accepted, entered directly or as a canonical `https://www.youtube.com/channel/UC...` URL with the default port and no query or userinfo; handles are not resolved. Each poll fetches one fixed URL built from the validated ID with no cookies (`credentials: 'omit'` explicitly set), no redirects, a 15-second timeout, and a streamed response bounded at 1 MiB; unused error and rate-limit response bodies are canceled to release connections. Feeds are parsed by a minimal strict XML tokenizer that accepts the canonical structure (Atom namespace, the fixed YouTube `yt:` namespace, plain text, predefined and numeric entities) and also structurally parses the declared canonical `media:` namespace (`http://search.yahoo.com/mrss/`) and `xml:lang` as ignored metadata: `media:*` elements may nest freely and are never read, and root-level `xmlns:media` must bind exactly the canonical media URI. It still rejects DOCTYPE, ENTITY, comments, CDATA, undeclared or wrong-URI prefixes, and truncated markup. Namespace declarations are honored only on the feed element; rebinding `xmlns` or `xmlns:*` in child attributes is rejected, and prefixed attributes are accepted only for declared `yt:`, declared `media:`, and `xml:` (only `xml:lang` with a valid value), so fake or reidentified fields cannot be promoted to identity data. Nothing is expanded against external references: entity resolution is limited to the five predefined entities and numeric character references, and attribute values are validated but never decoded. `yt:channelId` must match the configured channel: live canonical feeds echo the feed-root channel ID without the `UC` prefix while entries carry the full `UC`-prefixed ID, and both forms are accepted only when they resolve to the one validated configured ID; `yt:videoId` must be exactly 11 characters; `published` must be a valid non-future timestamp. Remote titles are never stored, which limits parser and Markdown injection. The first successful poll baselines the finite feed and queues nothing; an explicit `discover --backfill` queues every channel ID currently returned by the feed that is absent from `catalog.videos`, including IDs the baseline already marked seen, and re-running backfill never rewrites existing video state. Regular polls queue only unseen IDs, and seen IDs are retained even when entries fall out of the finite feed so replays never re-queue; no complete historical coverage is claimed. Failed fetches or rejected feeds do not advance a channel's baseline or seen set and stay visible on the dashboard; other channels' successes persist. HTTP 429 records a capped Retry-After (default 15 minutes, maximum 1 hour) and later runs skip the channel until the cooldown ends. Removing a channel only removes configuration; queued videos and reports are retained. Tests inject a fetch implementation; no production path accepts arbitrary feed URLs.

Daily scheduling, live subscription invocation, distributable container packaging, and three-video acceptance remain pending. Monitoring has no enable command in this slice.
